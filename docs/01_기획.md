# 기획 — 기술 스택·시스템 구조·설계 결정

## 1. 기술 스택과 선택 근거

| 항목 | 선택 | 근거 |
|---|---|---|
| 프레임워크 | Next.js 16 App Router | 아키텍처 요구사양. Vercel 배포와 정적 생성이 이 사이트(읽기 전용 연구 페이지)와 맞는다 |
| 언어 | TypeScript strict | 핵심 엔지니어링 사양. `Metric.value: number \| null` 같은 "모름" 표현을 타입으로 강제하기 위해 필요 |
| 스타일 | Tailwind CSS v4 | 표준 UI 스타일링 사양. `@tailwindcss/postcss` 플러그인 방식 |
| 테스트 | Vitest + React Testing Library + jsdom | TDD 검증 사양. Jest 대비 설정이 짧고 Vite 기반이라 시작이 빠르다 |
| E2E | **미설치** | T09 외에는 필요가 없었다. 불필요한 의존성을 늘리지 않는다는 원칙에 따라 AI B 판단에 위임 |
| 데이터 저장 | TypeScript 리터럴 (`src/data/*.ts`) | 데이터가 수십 건 규모이고 빌드 타임에 고정된다. DB나 CMS는 과잉 |

같은 워크스페이스의 `realtime-info-board` 프로젝트에서 이미 검증된 설정 파일 구성을 재사용했다
(`vitest.config.ts`, `eslint.config.mjs`, `postcss.config.mjs`, `tsconfig.json`).
새로 발명하지 않은 이유: 동작이 확인된 조합이고, 워크스페이스 안에서 설정이 일관되면 유지 비용이 낮다.

## 2. 시스템 구조

```
데이터 (src/data/*.ts)
   │  Source / ModelEntry / Metric / ChecklistItem / TestCase
   ▼
컴포넌트 (src/components/*.tsx)
   │  SourceLink / MetricCard / HandoverChecklist / SectionHeader / SiteNav
   ▼
페이지 (src/app/**/page.tsx)
      데이터를 import 해서 컴포넌트에 넘기기만 한다. 로직 없음
```

전 페이지가 정적 생성(SSG)된다. 서버 컴포넌트만 쓰며 클라이언트 컴포넌트가 하나도 없다
(`"use client"` 0건). 상태도 데이터 페칭도 없기 때문이다.

## 3. 핵심 설계 결정

### 3-1. "모름"을 `null`로, "0"과 구분한다

```ts
type Metric = { value: number | null; ... }
```

`formatMetric()`은 `null`과 `NaN`을 `"N/A"`로, `0`은 `"0"`으로 렌더링한다.
이유: 실험 지표에서 "아직 측정 안 함"과 "측정했더니 0"은 완전히 다른 사실이다.
둘을 같은 화면으로 보여주면 보고서 자체가 거짓이 된다.
`src/components/metric-card.test.tsx`가 이 구분을 테스트로 고정했다.

### 3-2. 확인하지 못한 수치는 아예 넣지 않는다

`/models` 페이지의 컨텍스트 창 크기·가격·사용량 한도는 자주 바뀐다.
원문 확인 없이 쓰면 그 순간부터 거짓 정보가 되므로, AI A는 `src/data/models.ts`를 만들지 않고
`ModelEntry` 타입만 정의한 채 페이지 전체를 AI B에게 넘겼다.
`ModelEntry.contextWindow`가 `string | null`인 것도 같은 이유다.

### 3-3. `NAV_LINKS`가 정보 구조의 단일 진실 공급원

네비게이션 렌더링과 T02 테스트가 같은 배열(`src/components/site-nav.tsx`)을 참조한다.
경로를 바꾸면 두 곳이 자동으로 따라간다. 테스트에 경로를 다시 적어 두면 두 목록이 어긋난다.

부작용: 아직 만들지 않은 5개 페이지 링크가 404로 연결된다. 이는 의도된 상태다 —
링크를 지우면 T02가 요구하는 7개 경로 계약이 깨진다.

### 3-4. url 없는 출처의 fallback

`SourceLink`는 `url`이 `null`이거나 공백 문자열이면 `<a>` 대신 `<span>`을 쓰고
"링크 확인하지 못함"을 표시한다. 빈 `href=""`는 현재 페이지로 이동해 버려서 사용자를 속인다.

## 4. 알고리즘 / 로직

이 사이트에는 알고리즘이라 할 만한 것이 `formatMetric()` 하나뿐이다.

```
formatMetric(metric) → string
  value가 null 또는 NaN  → "N/A"
  그 외                   → `${value}${unit}`
```

나머지는 전부 데이터 → 리스트 렌더링이다. 의도적으로 그렇게 유지한다.

## 5. 향후 확장 시 주의점

- `/models` 비교 테이블은 이 사이트에서 가로로 가장 넓은 요소가 된다.
  반드시 `overflow-x-auto` 컨테이너 안에 넣을 것. 페이지 본문이 가로 스크롤되면 T09 위반이다.
- `/tests` 페이지는 `TestCase` 타입(`atHandover` / `final`)을 이미 갖고 있다.
  `src/data/tests.ts`를 만들고 `docs/HANDOVER_AI_A_TO_B.md` 4장 표의 값을 그대로 옮기면 된다.
