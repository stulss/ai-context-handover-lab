# 요구사항 — AI Context Handover Lab

## 1. 목적

LLM/AI 에이전트 간 컨텍스트 인계(Context Handover)를 설명하는 연구형 웹사이트를 만들고,
동시에 그 사이트 자체를 AI A → 인계 문서 → AI B 방식으로 개발해 실험 결과를 사이트에 기록한다.

핵심 질문: **전체 대화 이력 없이, 구조화된 상태 문서와 코드 저장소만으로 다른 AI가 개발 작업을 성공적으로 이어갈 수 있는가?**

## 2. 기술 스택 (고정)

| 항목 | 선택 |
|---|---|
| 프레임워크 | Next.js App Router (16.x) |
| 언어 | TypeScript (strict) |
| 스타일 | Tailwind CSS v4 (`@tailwindcss/postcss`) |
| 단위/컴포넌트 테스트 | Vitest + React Testing Library + jsdom |
| Lint | ESLint 9 + eslint-config-next |
| 배포 대상 | Vercel 호환 |

E2E(Playwright)는 **설치하지 않았다**. 필요하면 AI B가 추가 판단한다.

## 3. 기술 원칙

- `any` 타입 금지.
- 데이터와 UI를 분리한다. 조사·실험 데이터는 `src/data/*.ts`에 둔다.
- JSX 안에 긴 조사 텍스트나 출처 데이터를 하드코딩하지 않는다.
- 페이지는 얇게 유지하고 복잡한 UI는 `src/components/`로 분리한다.
- 반응형 UI(모바일 우선), 의미 있는 heading 구조, 버튼/링크 구분, 접근성 속성 적용.
- 불필요한 라이브러리를 추가하지 않는다.
- 테스트를 삭제·skip·약화하여 통과시키지 않는다.

## 4. 출처 처리 원칙 (엄격)

- 출처가 없는 모델 한도, 가격, 성능 수치, 논문 결과를 **만들어내지 않는다**.
- 출처 데이터는 최소한 다음 필드를 가진다: 제목 / 기관·저자 / 발행 연도·날짜 / URL / 인용한 핵심 주장.
- 외부 URL은 클릭 가능한 링크로 표시한다. URL이 없으면 링크 대신 평문 + "링크 확인하지 못함" 안내.
- 확인하지 못한 값은 `null`로 두고 UI에서 `N/A`로 표시한다. **0으로 치환 금지.**

## 5. 정보 구조 (7개 페이지)

| 경로 | 내용 |
|---|---|
| `/` | 프로젝트 소개, 핵심 질문, AI A → Handover → AI B 흐름, 주요 실험 지표 요약 카드 |
| `/handover` | Context Handover 개념, 좋은 인계 문서의 필수 요소, 인계 구조 설명 |
| `/models` | AI 코딩 도구의 컨텍스트 창·사용량 제한·모델 전환 전략 비교 테이블. "고정 메시지 한도" vs "토큰/계산량 기반 한도" 차이 설명 |
| `/metrics` | AI-Driven Development 생산성 지표(시간·요청 수·테스트 통과율·재작업률·비용·회귀 결함·인계 누락률)와 DORA / SPACE / Copilot usage metrics 프레임워크 소개 |
| `/experiment` | AI A → handover → AI B 실험 타임라인, 역할 분담, 시간·요청 수 비교, 테스트 상태 변화 |
| `/tests` | 10개 테스트의 상태. 인계 시점 vs 최종 완료 시점 비교 |
| `/sources` | 연구 자료·공식 문서 링크와 조사 기준일 |

## 6. 완료 조건

- `docs/test-plan.md`의 T01~T10을 모두 충족한다.
- 기존 테스트를 삭제하거나 약화하지 않는다.
- `npm run lint`, `npm run build`, `npm run test`가 모두 성공한다.
- 주요 페이지가 모바일 뷰포트에서 깨지지 않는다.
- 출처 데이터가 클릭 가능한 링크로 렌더링된다.

## 7. 범위 밖

- 사용자 인증
- 데이터베이스 연동
- 실제 AI API 호출 (이 사이트는 실험 결과를 **기록**할 뿐 AI를 호출하지 않는다)
- 다국어 지원
