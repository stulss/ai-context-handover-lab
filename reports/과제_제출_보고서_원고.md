# 대화가 끊겨도 이어지는 프로젝트 — AI Context Handover Lab

## 1. 제출 정보

- 결과물 주소: https://ai-context-handover-lab.vercel.app/
- 소스 주소: https://github.com/stulss/ai-context-handover-lab
- 실험 주제: 대화 전문 없이 저장소와 구조화된 인수인계만으로 다른 AI가 개발을 이어갈 수 있는가
- 작업 순서: AI A 시작 → AI A 종료·인수인계 → AI B 시작 → AI B 완료 → agy 독립 검증 → 사용자 배포

## 2. 왜 이 실험을 했는가

긴 작업의 연속성을 한 AI의 기억에 맡기면 대화 길이와 모델 교체에 따라 상태가 유실된다. 이 프로젝트는 대화 전문 대신 저장소, 고정 검사, 실행 명령, 현재 상태, 남은 문제, 금지 범위를 전달하는 운영 방식을 시험했다. 핵심 질문은 “전체 대화 이력 없이도 다음 AI가 같은 검사를 실행하고 남은 기능을 완성할 수 있는가?”였다.

## 3. 실험 설계

AI A는 Next.js 기반 연구형 사이트의 기반과 홈·인계 페이지를 만들고 계획된 시점에 멈췄다. 인계 문서에는 목표, 현재 상태, 실행 명령, 통과 검사, 남은 문제, 다음 행동, 건드리지 말 것의 일곱 칸을 남겼다. AI B는 AI A의 대화 전문을 받지 않고 저장소와 인계 문서만으로 테스트 상태를 재현한 뒤 `/sources`, `/metrics`, `/models`, T08, T09, `/experiment`, `/tests`를 완성했다. agy는 최종 테스트와 모바일 스크린샷을 독립 검증했다.

새 체크리스트는 프로젝트 완료 후 제공됐다. 따라서 작업 전에만 만들 수 있는 공통 시간·요청 상한, AI A 시작 버전, 새 폴더 재현 증거는 소급 작성하지 않고 “증거 없음”으로 구분한다.

## 4. 고정 검사 10개

| ID | 입력 | 관찰 가능한 기대값 |
|---|---|---|
| T01 | `/` | 제목과 핵심 질문이 보인다 |
| T02 | `NAV_LINKS` 7개 | 중복 없는 올바른 href가 보인다 |
| T03 | `/handover` | 인계 필수 항목 7개와 “왜” 설명이 보인다 |
| T04 | `/models`, 데이터 있음/없음 | 비교표 또는 빈 상태가 보인다 |
| T05 | `/metrics`, METRICS 6건 | 모든 카드와 DORA·SPACE가 보인다 |
| T06 | URL이 null/공백인 출처 | 링크 대신 평문과 누락 안내가 보인다 |
| T07 | 값 null/NaN/0 | 각각 N/A/N/A/0으로 구분된다 |
| T08 | 존재하지 않는 경로 | 404 안내와 홈 링크가 보인다 |
| T09 | 375px 주요 5페이지 | 본문 가로 넘침이 없고 표만 자체 스크롤된다 |
| T10 | test/lint/build/typecheck | 전부 exit 0, skip·only·todo 0건이다 |

## 5. AI A 중단 시점

- 실제 작업시간: 약 12분
- 요청 수: 8회
- 단위 테스트: 5 files / 13 tests PASS
- 고정 검사 판정: PASS 6/10, FAIL 0/10, 미구현·미검증 4/10
- 남은 기능: `/sources`, `/metrics`, `/models`, `/experiment`, `/tests`, T08, T09
- AI A 종료 스냅샷: `4b9be8f` (Git은 이후 생성되어 동시점 ID가 아닌 보존 커밋)

## 6. 일곱 칸 인수인계

1. 목표 — 무엇을 완성해야 하는가
2. 현재 상태 — 구현·미구현을 구분한다
3. 실행 명령 — install, test, lint, build, dev
4. 통과 검사 — 실제 건수와 PASS ID를 기록한다
5. 남은 문제 — 재현 방법과 관련 파일을 적는다
6. 다음 행동 — P0 순서와 완료 판정을 적는다
7. 건드리지 말 것 — 테스트 약화, 수치 추정, null→0, 링크 삭제, 무단 Git 초기화 금지

## 7. AI B의 재개와 완료

AI B는 첫 실행에서 AI A 문서의 13 tests PASS를 독립 확인했다. 이후 기존 `MetricCard`, `SourceLink`, `NAV_LINKS`를 재사용하고 미측정 값은 N/A로 유지했다. 모델 수치는 공식 출처가 없어 “확인하지 못함”으로 표시했다. 브라우저 수동 캡처가 불가능한 상황에서는 Playwright 375×812 E2E를 추가해 본문 overflow와 모델 표 자체 스크롤을 자동 검증했다.

최종 결과는 Vitest 10 files / 20 tests PASS, Playwright 2 tests PASS, lint/build/typecheck PASS였다. 고정 검사 T01~T10은 PASS 10/10이며 기존 테스트 삭제·완화·기대값 변경은 0건이다.

## 10. 짧은 확인 방법 4줄

1. 위치 — https://ai-context-handover-lab.vercel.app/
2. 행동 — `Context Handover` → `테스트 현황` → `실험 기록`을 연다.
3. 통과 모습 — 인계 7항목, T01~T10 PASS, A → Handover → B 순서가 보인다.
4. 안 될 때 모습 — 로그인·404·누락 항목·FAIL·본문 가로 스크롤이 보인다.

## 11. AI와 나의 판단 3줄

1. AI에게 맡긴 일 — AI A에는 초기 구현과 인계 문서, AI B에는 남은 기능과 테스트·모바일 검증을 맡겼다.
2. 직접 판단한 일 — push는 Claude에게 맡기고 Vercel 배포는 직접 수행했으며 증거 작성자와 한국어 경고를 요구했다.
3. AI 제안을 따르지 않은 일 — 자동 배포와 출처 없는 수치 보완을 허용하지 않고 미계측 값은 N/A로 남겼다.

## 12. 새 체크리스트 감사 결과

강하게 충족한 항목은 실행 순서, 인계 7항목, AI B의 대화 없는 재개, 서로 다른 서비스, 테스트 보존, PASS 10/10, 공개 URL, 개인정보·비밀값 0건이다.

보완이 불가능하거나 추가 증거가 필요한 항목은 사전 공통 시간·요청 상한, AI A 시작 버전, 새 폴더 재현, AI B 실제 시간·요청 수, 공개 비교 화면의 익명화다. 체크리스트가 사후 변경되었으므로 이 값을 만들어내지 않는다.

## 13. 결론과 다음 도구 선택 기준

인계 문서는 대화 기억의 대체물이 아니라 실행 가능한 상태 스냅샷이어야 한다. 이번 실험은 AI B가 6/10 상태를 재현하고 10/10까지 완성했다는 점에서 기술적 연속성은 입증했다. 동시에 사전 계측 설계가 없으면 이후의 비교 품질은 복구할 수 없다는 한계도 확인했다.

다음 작업에서는 설계·중단 지점 정리에는 문서화가 강한 도구를, 명확한 테스트 계약을 이어 구현하고 반복 검증하는 작업에는 실행·수정 루프가 빠른 도구를 먼저 선택한다.
